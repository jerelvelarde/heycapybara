# Kite OS Learning Implementation Plan

> Execute the approved plan using subagent-driven-development for the native helper and review; integrate the coupled desktop/runtime/UI work in this session.

**Goal:** A runnable macOS companion that records cross-app workflows, creates reviewed skills, and connects AG-UI runs to CopilotKit Intelligence automatic learning.

**Architecture:** Electron main owns capture and persistence through narrow IPC. A Swift JSONL helper supplies macOS accessibility events. React renders the workspace and buddy; a loopback authenticated CopilotKit runtime streams AG-UI events and delivers learned skills.

**Tech Stack:** Electron, React, TypeScript, Vite, Swift/AppKit, CopilotKit runtime, AG-UI.

- [x] Foundation: package/build configuration and shared IPC contracts in src/types.ts; install pinned dependencies.
- [x] Native recorder: native/Recorder.swift, scripts/build-native.sh; compile helper; JSONL start/stop events, permission status, app/click/shortcut context. Delegate independent implementation.
- [x] Persistence: electron/store.ts and tests/store.test.ts; test recording lifecycle, unique skill IDs, approval, validation and filesystem traversal rejection before implementation.
- [x] Runtime: server/runtime.ts; use actual installed API signatures, same container for ingestion/delivery, private credentials, loopback bearer access; no configured keys means explicit offline state.
- [x] Desktop: electron/main.ts and preload.ts; windows, shortcut, recording lifecycle, event redaction, snapshot, permission flow, skill export, limited approved actions.
- [x] Workspace: src/App.tsx and styles.css; recording timeline, draft review, library, assistant, integration setup; actual IPC actions, empty states and errors.
- [x] Validation: typecheck, tests, renderer build, native compilation; launch Electron and exercise local recording/skill review/export with test evidence. Review native boundary and overall spec/quality; fix findings before final status.

Cloud verification requires project key, existing learning container, and provider key. Document exact setup and verification without claiming a live connection until observed.
